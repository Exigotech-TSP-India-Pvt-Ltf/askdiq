## Purpose

AskDIQ is a retrieval-augmented generation (RAG) assistant that answers questions about
**DeployIQ** (Exigo Tech's security and compliance platform) using only the content of the
DeployIQ website knowledge base. Answers are generated by Azure OpenAI from retrieved
knowledge-base chunks, checked for groundedness, and returned with their sources.

Brand names are configuration, not code: `BRAND_NAME=DeployIQ`,
`BRAND_ASSISTANT_NAME=AskDIQ`, `BRAND_COMPANY_NAME=Exigo Tech`
(`backend/app/core/config.py`), overridable at runtime via the `brand_settings` row
(Settings > Branding).

The repository has two deliverables:

| Part | Path | What it is |
|---|---|---|
| Backend | `backend/` | FastAPI service: `/query` RAG pipeline, sessions, ingestion, governance, analytics, auth, job worker. Entry point `backend/main.py` (`main:app`). |
| Admin dashboard | `frontend/` | Next.js 14 app (package `deploy-iq-frontend`): internal console for chat, documents, usage, governance, evaluation, feedback, insights, users, branding. Talks to the backend only through its server-side proxy. |

The public website chat widget is **not** in this repository. It is built by the website
frontend team and calls the backend server-to-server (see
[Website integration](10-website-integration.md)).

### Guardrails

| Stage | Checks |
|---|---|
| Pre (before retrieval) | Length (`MAX_QUERY_LENGTH=2000`), prompt-injection patterns (`UNSAFE_PATTERNS`), spam (URLs, promo phrases, gibberish ratio), noise-token stripping |
| Retrieval | Empty result (`off_topic`; hotfix: `no_sources`), top score below `MIN_RETRIEVAL_SCORE=0.15` (`off_topic`), indirect prompt injection in retrieved chunks (chunks dropped) |
| Post (after generation) | Unsupported `$`/`%` figures, negative-answer allowance, embedding-cosine groundedness vs `GROUNDEDNESS_THRESHOLD=0.45` (`possible_hallucination`) |
| Output | Fixed polite fallback answers per flag; outcome recorded (`answered`, `blocked`, `ungrounded`, `llm_failed`, `conversational`) |

## Glossary

| Term | Meaning in this project |
|---|---|
| RAG | Retrieval-augmented generation: retrieve relevant knowledge-base chunks, then ask the LLM to answer from them only. |
| Knowledge base (KB) | The DeployIQ website content, canonical markdown in `documents` / `chunks`; bundled sources in `backend/data/real_docs/*.md`. |
| Canonical markdown | The normalised, PII-redacted markdown stored per document (`documents.canonical_markdown`) that chunking runs on. |
| Chunk | A section of a document stored with its embedding and metadata (`chunks` table). Identified by id and content hash. |
| Content hash | SHA-based hash of canonical text (document) or chunk text; drives "unchanged" detection and incremental re-embedding. |
| Embedding | 1536-float vector from `text-embedding-3-small`, stored in a pgvector column. |
| Recall (candidate pool) | First retrieval step: cosine-distance search returning `max(top_k x RETRIEVAL_CANDIDATE_MULTIPLIER, RETRIEVAL_CANDIDATE_MIN)` candidates. |
| Rerank | Reordering the candidate pool with a cross-encoder (`fastembed`); scores reported stay cosine similarity. |
| Cross-document quota | Final selection that gives up to `CROSS_DOC_QUOTA_MAX_DOCUMENTS=3` top documents a fair share of the `top_k` slots. |
| Query decomposition | Rule-based split of a compound question into sub-queries, each embedded and searched separately, merged round-robin. |
| Groundedness | Post-check: max cosine similarity between the answer embedding and source chunk embeddings, compared with `GROUNDEDNESS_THRESHOLD`. |
| Guardrail | A rule that blocks or flags input or output (pre-checks, retrieval checks, post-checks). Results appear as `guardrail_flags`. |
| Outcome | Canonical result of an exchange: `answered`, `conversational`, `blocked`, `ungrounded`, `llm_failed` (`backend/app/governance/outcomes.py`; the orchestrator hint `empty_llm_output` maps to `llm_failed`). |
| Visitor / `X-Client-Id` | Production line: a browser-scoped id the website sends to partition chat sessions. Not a security boundary. On the revamp line it is forwarded but never trusted as identity; dashboards group "visitors" by client IP. |
| Actor | The identity a request is attributed to: `X-Client-Id` (production) or the signed-in user's email (revamp). |
| Session (chat) | A server-side conversation (`chat_sessions`) with an idle expiry; not the same as an auth session. |
| Session (auth) | A sign-in session (`auth_sessions`), id in the httpOnly cookie, sent to the backend as `X-Session`. |
| Turn / exchange | One user question plus its assistant answer; two `chat_messages` rows sharing a `turn_index`. |
| Request id | UUID assigned per HTTP request by `LatencyMiddleware`; returned as `X-Request-ID`; key for traces. |
| Trace | The governance view of one request: audit row, stage timings, sources and scores, tokens, cost, evaluation. |
| Stage timings | Per-request milliseconds for `embedding`, `retrieval`, `reranker`, `guardrail_pre`, `llm`, `guardrail_post` (`latency_metrics`). |
| Stage tokens | Tokens split by stage: LLM prompt/completion/reasoning/cached, query embedding, guardrail embedding, ingest embedding. |
| Audience | Data scope for dashboards: `overview` (all), `users` (real traffic), `testing` (test IPs). |
| Test IP | An IP, prefix or CIDR marked as internal testing traffic (`/admin/usage/test-ips`). |
| Golden case | A conversation turn promoted from feedback into a regression test case (`eval_promoted_cases`), re-runnable as a job. |
| Triage | Feedback workflow states `new`, `reviewed`, `promoted`, `dismissed`. |
| Taxonomy | Stable insight codes (intents, bot quality, issues) with editable labels (`insight_taxonomy`). |
| Online evaluation | Background quality sampling of live answers (as opposed to offline dataset runs). |
| Circuit breaker | `CircuitBreaker` in `backend/app/core/circuit.py`: after 5 transient LLM failures in 60 s, calls fail fast for 30 s, then one probe. |
| LLM gate | Process-wide cap on concurrent `/query` requests (`LLM_MAX_CONCURRENCY=64`); over it, 429 with `Retry-After`. |
| Single flight | Collapsing identical concurrent computations into one (`SingleFlight` in `concurrency.py`). |
| `gather_scoped` | Run DB aggregates in parallel, one short-lived `AsyncSession` per task, bounded by `AGG_MAX_CONCURRENCY`. |
| Job queue | `jobs` table; workers claim with `FOR UPDATE SKIP LOCKED`; retries with backoff; dedupe keys. |
| SKIP LOCKED | Postgres row-lock option that skips rows already locked by another transaction, so many workers can claim jobs without blocking each other. |
| Transactional outbox | Enqueuing a job in the same transaction as the data it refers to (`enqueue_in`). |
| LISTEN/NOTIFY | Postgres pub/sub. Used as the cross-worker event bus (`askdiq_events` channel) for cache invalidation and incident wake-ups. |
| UNLOGGED table | Postgres table without WAL (faster, lost on crash). `rate_limit_buckets` is one. |
| SSE | Server-Sent Events: one-way `text/event-stream` used by `/admin/governance/stream`. |
| ETag / 304 | Weak entity tag on cacheable GET responses; a matching `If-None-Match` returns 304 Not Modified (`backend/app/core/http_cache.py`). |
| problem+json | RFC 9457 error body (`type`, `title`, `status`, `detail`, `request_id`) used by all error responses (`backend/app/core/exceptions.py`). |
| Entra ID | Microsoft Entra ID (Azure AD), the identity provider for dashboard SSO. |
| OIDC | OpenID Connect; the sign-in protocol on top of OAuth 2.0. |
| PKCE | Proof Key for Code Exchange (S256): binds the authorization code to a secret verifier kept server-side. |
| `state` / `nonce` | OIDC anti-CSRF value (also bound to the `askdiq_oidc_state` cookie) and ID-token replay guard; stored single-use in `oidc_states`. |
| Mock IdP | Local Entra look-alike for development (`AUTH_DEV_MOCK=true`). |
| BFF proxy | Backend-for-frontend: the Next.js route `frontend/app/api/proxy/[...path]/route.ts` that adds the service key and session, so the browser never talks to FastAPI directly. |
| Service key | `X-API-Key` value (`API_KEY_NAME` on the backend, `API_KEY` on the frontend server). |
| CSRF marker | `X-Requested-With: askdiq` plus an `Origin` equal to `APP_BASE_URL`, required on state-changing session requests. |
| Advisory lock | Postgres application lock (`pg_advisory_xact_lock`), used per document name in ingestion and for insights LLM batches. |
| TPM / RPM | Azure OpenAI tokens / requests per minute quotas, tracked by `quota_monitor`. |
